# AssetBox 디자인 가이드

AssetBox 데스크톱 앱의 화면을 추가하거나 수정할 때 사용하는 기준입니다. 3D 모델을 충분히 볼 수 있는 공간을 확보하고, 파일 탐색과 검사 결과를 빠르게 읽을 수 있도록 합니다.

수치와 클래스의 실제 정의는 [App.css](../src/App.css)에 있습니다. 공통 디자인을 바꾸면 코드와 이 문서를 같은 변경에서 갱신합니다. 사용 방법은 [활용 가이드](GUIDE_KO.md)를 참고하세요.

## 1. 기본 원칙

- **모델이 중심이다.** 탐색, 검사 정보, 저장 기능은 각자의 영역에 배치합니다. 상시 사용하는 버튼을 캔버스 위에 겹쳐 놓지 않습니다.
- **같은 역할에는 같은 표현을 쓴다.** 버튼, 제목, 보조 설명, 상태는 기존 클래스와 컴포넌트를 재사용합니다.
- **색과 글을 함께 읽을 수 있어야 한다.** 선택 상태에는 테두리와 배경을, 검사 결과에는 등급이나 기호를 함께 표시합니다.
- **다음 행동이 보여야 한다.** 빈 화면에는 시작 방법, 처리 중에는 진행 상태, 오류에는 가능한 복구 행동을 제공합니다.
- **정보는 현재 파일과 일치해야 한다.** 파일을 바꾸면 이전 검사 결과와 내보내기 동작을 노출하지 않습니다.

현재 앱의 UI 문구는 영어를 사용합니다. 새 기능도 기존 용어를 따르고, 파일명과 경로는 원문 그대로 표시합니다.

## 2. 화면 구조와 크기 대응

| 영역                     | 포함할 내용                                       | 배치 기준                                              |
| ------------------------ | ------------------------------------------------- | ------------------------------------------------------ |
| 앱 헤더                  | 브랜드, `Files`, `Open folder`                    | 높이 60px, 창 상단 고정                                |
| 왼쪽 Files 패널          | 폴더 이동, 검색, 필터, 파일 목록, 일괄 검사       | 독립적인 목록 스크롤                                   |
| 중앙 Preview             | 현재 파일명, 캔버스, 보기 모드, 배경, `Fit model` | 남은 너비를 사용, 최소 너비 계산에 `min-width: 0` 적용 |
| 오른쪽 Asset information | 파일 요약, 검사 항목, 텍스처, 내보내기            | 내용만 스크롤, 저장 버튼은 패널 하단 유지              |

각 영역의 제목 행 높이는 45px입니다. 앱 전체 대신 파일 목록과 정보 내용을 각각 스크롤합니다. 세로 flex 영역에는 `min-height: 0`을 적용해 내용이 창 아래로 밀려나지 않도록 합니다.

창 설정은 [tauri.conf.json](../src-tauri/tauri.conf.json)을 따릅니다.

| 조건                 | 현재 기준                                                                    |
| -------------------- | ---------------------------------------------------------------------------- |
| 기본 창              | 1280 × 800px                                                                 |
| 최소 지원 창         | 900 × 600px                                                                  |
| 파일 패널            | 기본 저장 폭 300px, 리사이즈 값 240–560px, 실제 표시 폭은 창 너비의 34% 이하 |
| 정보 패널            | 펼침 304px, 접힘 68px                                                        |
| 창 너비 ≤ 1100px     | 정보 패널 280px, 파일 패널 최대 28vw, 보조 조작 안내와 모드 단축키 배지 숨김 |
| Preview 너비 ≤ 570px | 보기 모드를 3열 × 2행으로 배치                                               |

보기 모드의 줄 수는 **창 전체가 아닌 Preview 컨테이너의 너비**로 결정합니다. 파일 패널 리사이즈나 정보 패널 접기 후에도 확인해야 합니다. 최소 창에서 버튼 이름을 없애거나 필수 기능을 화면 밖으로 밀어내는 방식으로 공간을 확보하지 않습니다.

로딩·드롭 안내와 Retopo 진단처럼 캔버스에 종속된 정보만 오버레이로 표시합니다. 오버레이는 캔버스 경계를 지키고 긴 내용에는 자체 스크롤을 제공합니다.

## 3. 색상

새 UI의 색상은 `App.css`의 CSS 변수를 사용합니다. JSX마다 비슷한 색을 새로 만들지 않습니다.

| 토큰               | 값                          | 용도                                       |
| ------------------ | --------------------------- | ------------------------------------------ |
| `--bg-primary`     | `#171c26`                   | 작업 영역 기본 배경                        |
| `--bg-secondary`   | `#141922`                   | 헤더, 탐색기, 정보 패널, 보기 도구 배경    |
| `--bg-panel`       | `#1d2430`                   | 버튼과 검사 그룹 제목 등 한 단계 구분된 면 |
| `--overlay-bg`     | `rgba(23, 29, 40, 0.97)`    | 모델 위에서도 읽히는 오버레이              |
| `--border`         | `#30394a`                   | 패널과 컨트롤 경계                         |
| `--text-primary`   | `#edf0f6`                   | 파일명, 주요 값, 일반 버튼                 |
| `--text-secondary` | `#b0b9c9`                   | 항목 이름, 설명                            |
| `--text-muted`     | `#9ca8bb`                   | 경로, 파일 크기, 보조 안내                 |
| `--text-faint`     | `#78849a`                   | 경로 구분자 등 보조 장식                   |
| `--accent`         | `#ff8da2`                   | 선택된 글자·아이콘, 키보드 초점            |
| `--accent-soft`    | `rgba(255, 141, 162, 0.12)` | 선택 상태의 배경                           |
| `--accent-solid`   | `#ad3453`                   | 주요 행동의 채움 배경, 흰 글자와 사용      |
| `--accent-hover`   | `#bd405f`                   | 주요 행동의 hover 배경                     |
| `--success`        | `#73dda5`                   | 성공 의미의 강조                           |
| `--warning`        | `#f2ca72`                   | 경고 값과 안내                             |
| `--danger`         | `#ff929c`                   | 문제 값과 오류 강조                        |

일반 검사 항목의 정상 값은 `--text-primary`로 표시하고, 경고와 문제에 색을 집중합니다. 밝은 `--accent`를 흰 글자의 버튼 배경으로 쓰지 않습니다. 중요 설명을 더 흐린 색이나 추가 opacity로 낮추지 않습니다.

### 기존 구현의 색상 구분

일부 상태 표현은 별도 팔레트를 사용하고 있습니다. 기존 화면을 수정할 때 이 차이를 확인하고, 새 컴포넌트에 값을 복사하지 않습니다.

- [ValidationBadge](../src/components/ValidationBadge.tsx)와 [파일 목록 등급 색](../src/lib/fileTree.ts)은 Checked `#4ade80`, Review `#fbbf24`, Needs attention `#f87171`, Incomplete `#9ca8bb`을 사용합니다. 상태 이름·색은 [validationStatus.ts](../src/lib/validationStatus.ts)를 공유하고, 배지는 `ValidationBadge`를 재사용합니다. 확인 불가를 성공색으로 표시하지 않습니다. 판정 의미는 [검사 가이드](VALIDATION_GUIDE.md)를 따릅니다.
- [ReportButton](../src/components/ReportButton.tsx)과 [ThumbnailButton](../src/components/ThumbnailButton.tsx)의 저장 성공·실패 상태도 위의 밝은 채움색을 사용하며, 글자는 어두운 `#111827`입니다.
- Three.js의 노멀·UV·밀도 시각화 색은 진단 의미를 전달하는 색입니다. UI 강조색 변경만을 이유로 함께 바꾸지 않습니다.
- [overlayStyle.ts](../src/lib/overlayStyle.ts)의 `BG_COLORS`는 캔버스 배경용입니다. `dark`, `neutral`, `light` 전환은 앱 전체 테마를 바꾸지 않습니다.
- 바닥 그리드는 기본으로 숨기고 `Grid` 버튼으로 켭니다. 검사 위치 강조 중에는 자동으로 숨기며, 강조를 해제하면 이전 설정을 복원합니다. 그리드의 중립색은 같은 파일의 `GRID_COLORS`에서 배경별로 정의합니다. UV 검사 무늬와는 별개이며 썸네일에는 포함하지 않습니다.
- 첫 모델 표시는 외부 조명 다운로드에 의존하지 않습니다. [PreviewLighting](../src/components/PreviewLighting.tsx)의 로컬 스튜디오 조명을 사용하고, 모델 배치 직후 카메라 변환과 화면을 갱신합니다. 파일을 선택한 뒤 캔버스를 클릭하거나 드래그하지 않아도 보여야 합니다.

오버레이를 추가할 때는 `OVERLAY_BG`, `OVERLAY_BORDER`, `OVERLAY_BACKDROP`을 재사용합니다. 현재 blur는 20px이며, 가독성은 충분한 배경 불투명도와 함께 확보합니다.

## 4. 타이포그래피와 긴 텍스트

시스템 글꼴 `system-ui, -apple-system, "Segoe UI", sans-serif`를 사용합니다. UI 표시를 위해 원격 폰트를 추가하지 않습니다.

| 역할           | 기준                             | 예시                         |
| -------------- | -------------------------------- | ---------------------------- |
| 본문           | `text-body`, 13px, 기본 행간 1.5 | 파일 목록, 검사 항목과 값    |
| 보조 설명      | `text-meta`, 12px                | 파일 크기, 경로, 임계값 안내 |
| 짧은 구역 라벨 | `text-label`, 11px               | Preview, 작은 메타 라벨      |
| 패널·그룹 제목 | 12px, 굵기 600                   | Asset information, Geometry  |
| 상세 파일명    | 16px, 굵기 600, 행간 1.4         | 정보 패널의 파일 제목        |
| 초기 화면 제목 | 23–32px, 굵기 650, 행간 1.25     | 폴더 열기 안내               |

작은 상태 배지·보기 모드·단축키 배지는 기존 전용 클래스의 10–12px 크기를 유지합니다. 이 예외를 일반 본문에 확대 적용하지 않습니다. 대문자와 넓은 자간은 짧은 구역 라벨과 포맷에 한정합니다.

- 파일 목록, 상단 파일명, 경로, 텍스처 파일명은 말줄임하고 `title`로 원문을 제공합니다.
- 상세 파일명과 오류 내용은 `overflow-wrap: anywhere`로 줄바꿈합니다.
- 검사 값은 오른쪽 정렬하고 `tabular-nums` 또는 `font-variant-numeric: tabular-nums`를 사용합니다.
- 경고의 임계값 설명은 값 아래에 별도 줄로 표시합니다.

## 5. 간격과 공통 컨트롤

기본 간격은 4·8·12·16·24px를 우선 사용합니다. 기존 컴포넌트의 6·10px 등 조밀한 간격은 해당 역할 안에서 유지합니다. 영역을 구분하려고 불필요한 카드나 테두리를 추가하지 않습니다.

| 요소             | 재사용 기준                                                                         |
| ---------------- | ----------------------------------------------------------------------------------- |
| 일반 버튼        | `.ui-button`: 최소 높이 34px, 6px 12px 패딩, 반경 7px                               |
| 아이콘 버튼      | `.icon-button`: 너비 34px, 최소 높이 34px, 명시적인 접근성 이름                     |
| 주요 행동        | `.ui-button.primary-button`: 최소 높이 42px, 10px 20px 패딩                         |
| 내보내기         | 기존 `ReportButton`, `ThumbnailButton`, `LogButton`; `.inspector-actions` 안에 배치 |
| 보기 모드        | `.view-mode`: 최소 높이 34px, 반경 6px, `aria-pressed`                              |
| 파일 도구 아이콘 | `.file-toolbar` 안의 버튼: 32 × 32px                                                |
| 검색 입력        | `.file-search`: 최소 높이 36px, 접근성 이름과 초점 테두리                           |
| 파일 행          | `FileTreePanel`의 `ROW_HEIGHT = 34`, 들여쓰기 `INDENT = 14`                         |
| 검사 그룹        | `.info-group`: 반경 8px, 그룹 사이 12px, 내부 가로 패딩 12px                        |
| 보조 컨트롤      | Fit model·배경 선택·파일 상태 바의 기존 28px 규격                                   |

파일 행 높이는 가상 목록의 렌더링, 스크롤, 키보드 이동에 함께 사용됩니다. CSS에서만 행 높이를 바꾸지 않습니다.

아이콘은 기존 SVG 스타일을 따릅니다. 보기 모드와 저장 버튼은 보통 16px, 파일 도구는 18px입니다. 모양만으로 의미를 짐작해야 하는 새 버튼에는 `aria-label`과 `title`을 제공합니다.

## 6. 상호작용과 상태

| 상태              | 지켜야 할 동작                                                                              |
| ----------------- | ------------------------------------------------------------------------------------------- |
| 파일 없음         | 시작 설명, `Open folder`, 드롭 방법과 지원 포맷을 표시                                      |
| 폴더만 열림       | 목록에서 모델을 선택하도록 안내                                                             |
| 검색 결과 없음    | 검색 중과 결과 없음을 구분                                                                  |
| 필터 적용         | 적용한 필터를 목록 위에 표시하고 바로 해제 가능하게 제공                                    |
| 파일 변경·검사 중 | 이전 검사 결과와 내보내기 버튼을 숨김. 늦게 끝난 이전 검사가 새 파일을 덮어쓰지 않도록 유지 |
| 검사 완료         | 파일 요약 → 카테고리별 검사 → 텍스처 순서 유지. 발견된 텍스처가 없어도 누락 안내 표시       |
| 일괄 검사         | 진행 수·전체 수와 취소 버튼, 이름 있는 `progressbar` 제공                                   |
| 내보내기          | `Saving…` 동안 중복 실행 차단 → `Saved!` 또는 `Failed`. 결과는 `aria-live`로 전달           |
| 모델 오류         | 원인과 `Logs`, 닫기를 표시하고 재시도 가능한 경우 `Retry` 제공                              |
| 정보 접기         | 68px 레일로 접고 다시 펼칠 수 있게 유지                                                     |

저장 버튼 위에는 `Save beside the source model`로 저장 위치를 설명합니다. 파일이 바뀌면 저장 버튼의 이전 성공·실패 상태도 초기화합니다.

### 검사 항목과 모델 위치 연결

- 위치 근거가 있는 검사 행만 `Locate in model` 버튼으로 만들고 선택 상태는 `aria-pressed`로 전달합니다. 실패 경로만 있는 항목은 `Show resource details`로 구분합니다.
- 선택한 행 아래에서 상세 정보를 펼치고 패널 내부를 스크롤해 보이게 합니다. 모델 위에 상세 카드가 겹치지 않게 유지합니다.
- 상세 정보는 항목 이름 → 대상 이동 → 오브젝트 경로 → 선택 대상의 수 → 관련 재질·텍스처 정보 순서로 표시합니다. 이전·다음 버튼은 34px 공통 규격, 직접 이동은 이름 있는 select를 사용합니다.
- 미리보기 위의 상태 줄은 레이아웃 공간을 차지하며, 항목 이름·표시 의미·`Clear focus`를 제공합니다. 좁은 화면에서도 캔버스나 보기 도구를 가리지 않습니다.
- 진단 위치는 `#ffbf47` 주황색 선·면·정점으로 표시합니다. 가려진 표면을 통과해 보임을 설명하고, 색만으로 의미를 전달하지 않습니다. 검사 심각도 색과 선택 위치 색은 역할이 다릅니다.
- 경고 클릭 시 Solid에서 위치를 보여주며, 강조 해제 시 이전 보기 모드로 돌아갑니다. 파일 전환·로드 실패 시 선택을 비웁니다. 검수 상태 저장과 연결하지 않습니다.
- 위치 표시 한계와 대상별 근거는 [검사 가이드](VALIDATION_GUIDE.md)를 따릅니다.

### 키보드와 접근성

- 선택 버튼은 `aria-pressed`, 접기 버튼은 `aria-expanded`, 파일 행은 `aria-selected`로 상태를 전달합니다.
- 전역 `:focus-visible`의 2px 강조 테두리를 유지합니다. 사용자 정의 초점 표시 없이 outline을 제거하지 않습니다.
- 파일 목록의 방향키 탐색은 목록에 초점이 있을 때만 동작해야 합니다. 검색 입력의 `↓`는 목록의 첫 항목으로 이동합니다.
- 문자 입력 중에는 보기 모드와 파일 이동 단축키가 실행되지 않도록 합니다. 플랫폼 조합키가 일반 문자 단축키와 충돌하지 않도록 합니다.
- `Escape`로 검색이나 메뉴를 닫을 수 있게 유지합니다.
- 패널 리사이즈는 마우스와 초점 받은 구분선의 `←`·`→` 키를 모두 지원합니다.
- 일반 색상 전환은 120ms를 기본으로 사용하고, `prefers-reduced-motion` 설정을 존중합니다.

보기 모드의 이름과 순서는 `Solid (1)`, `Wire (2)`, `Normals (3)`, `Normal Map (4)`, `UV (5)`, `Retopo (6)`입니다. 모드를 추가·변경하면 [ViewerToolbar](../src/components/ViewerToolbar.tsx), [Viewer3D](../src/components/Viewer3D.tsx)의 키보드 처리와 사용 문서를 함께 갱신합니다.

먼저 기존 클래스나 컴포넌트로 표현할 수 있는지 확인합니다. 여러 곳에 적용되는 변경은 공통 정의를 수정하고, 파일별 인라인 스타일로 덮어쓰지 않습니다. 모델 색·진행률처럼 데이터에 따라 달라지는 값은 인라인 스타일로 전달할 수 있습니다.

CSS reset은 `@layer base` 안에 둡니다. 레이어 밖에서 `* { margin: 0; padding: 0; }`을 선언하면 Tailwind의 여백 유틸리티를 덮어쓰므로 추가하지 않습니다.

새 규격이 필요한 경우 용도와 적용 범위를 이 문서에 함께 기록합니다. 문서에 표기된 수치와 코드가 다르면 먼저 실제 정의와 의도한 변경을 확인하고 둘을 맞춥니다. 문서만 수정해 구현이 바뀐 것으로 취급하지 않습니다.

## 8. UI 변경 확인 목록

- [ ] 1280 × 800과 900 × 600에서 패널, 도구, 저장 버튼이 겹치지 않는다.
- [ ] 파일 패널 폭 변경·숨김, 정보 패널 접기 후에도 모든 보기 모드에 접근할 수 있다.
- [ ] 긴 파일명·경로·오류, 많은 검사 항목과 긴 파일 목록에서도 스크롤과 줄바꿈이 유지된다.
- [ ] 빈 화면, 로딩, 검색 결과 없음, 필터, 경고·오류, 저장 중·완료·실패를 확인했다.
- [ ] 배경 3종과 보기 모드 6종에서 UI 가독성과 모델 표시를 확인했다.
- [ ] Tab 초점, 방향키 탐색, Escape, 입력 중 단축키 동작을 확인했다.
- [ ] 파일을 빠르게 바꿔도 이전 파일의 검사 정보와 저장 상태가 남지 않는다.
- [ ] 변경한 상호작용의 관련 테스트와 타입·빌드 검사를 수행했다.
- [ ] 공통 규격을 바꿨다면 이 문서와 연결된 UI 설명도 갱신했다.

동작을 변경한 경우 `npm test`, `npm run build:web`, `npm run lint`, `npm run format:check`를 사용하고 화면 검증을 병행합니다. CSS는 `npx prettier --check src/App.css`로 별도 확인합니다. 현재 `format:check` 스크립트는 TS/TSX만 검사합니다. 문서만 바꾼 경우에는 링크와 코드 기준을 대조하면 됩니다.

브라우저에서 파일 API를 모의 처리한 검증과 실제 Tauri 앱의 폴더 열기·드롭·파일 저장 검증은 구분해 기록합니다. 스크린샷과 테스트용 데이터는 공통 스타일의 기준 파일을 대체하지 않습니다.
